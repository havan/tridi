# Parametric wall shelf: design

Date: 2026-10-23. Status: approved by the user 2026-10-23.

## Intent

Small wall shelves holding devices while they charge: phones, PS4
controllers, chargers. A power strip with USB ports is fixed to the wall just below, so
charging cables come **up the wall from below** onto the shelf.

The shelf is generated by code, not drawn by hand. Every size and option is a parameter, so
anyone can produce the variant they need for their wall and printer. It is the first project in
**tridi**, a public GitHub repo for 3D-printed household items. More projects will follow, so the
repo is laid out for many projects with shared code.

## Goals

- One command produces print-ready files for any combination of the options below, at any size
  that fits the chosen printer.
- Every variant prints in PLA on a common FDM printer **without support material**.
- Holds small electronics reliably on a painted, plastered masonry wall with plastic dowels, or
  with tape or hot glue.
- Uses as little plastic as the user asks for: material-saving modes, and a volume/weight report
  for every build.
- The repo is ready to hold future household projects that reuse the shared code.

## Non-goals

- Automatically splitting a shelf that is too large for the printer into joined pieces. The build
  refuses instead (see "Printers").
- Heavy loads (books, plants). Design load: small electronics, about 1 kg spread over the shelf.
- A power-strip mount. That is a likely next project, not part of this one.
- odman's release machinery (part numbers, freezes, registers, datasheets). tridi is a hobby repo.

## Anti-goals: failures even if it "works"

- Personal information in tracked files: home paths, room or house details, or the user's own
  sizes. The repo is public (github.com/havan/tridi). Exceptions the user allowed: the author's
  name in `LICENSE`, and the author's name, email and GitHub username in commit metadata.
- A variant that needs slicer supports, or that silently doesn't fit the printer.
- Cable cutouts too narrow for a plug to pass through, which would mean unplugging everything to
  take the shelf down.
- Geometry that collides: a notch cutting through a bracket, a screw hole behind a bracket or
  beyond screwdriver reach. The build should catch these, not the printer.

## Constraints

- FreeCAD 1.1 via pixi (conda-forge), the same toolchain as the sibling `odman` repo. Geometry is
  Python using FreeCAD's `Part` module, run headless with `freecadcmd`.
- The FreeCAD MCP server (`freecad-mcp`, as configured in `odman/.mcp.json`) is in `.mcp.json` for
  interactive inspection and iteration. **The scripts are the source of truth.** Nothing is
  designed only in the GUI.
- Material is PLA. Warm phones while charging are fine (well below PLA's ~55–60 °C softening).
- Reference wall: painted plaster over masonry, with plastic dowels.
- Reference printer: Prusa i3 MK3S (250 × 210 × 210 mm), but nothing may be specific to it.
- Platforms (my call): `pixi.toml` declares linux-64, osx-arm64 and win-64 (conda-forge ships
  FreeCAD for all three). Only Linux is tested, and the README says so. Code uses `pathlib` and no
  shell-specific tricks. `.mcp.json` uses the Linux/macOS `freecadcmd` path, and the README gives
  the Windows path.

### Personal settings

The user's own presets go in `local.toml` at the repo root, which is gitignored. Its format is the
same as `presets.toml`. Committed presets use neutral names and sizes (e.g. `small`, `corner`,
`lean`), never anything about a specific home.

## Building

```
pixi run build shelf                                  # defaults
pixi run build shelf --preset corner                  # a named preset (presets.toml or local.toml)
pixi run build shelf --width 300 --supports above --mount cleat --notch back-left
pixi run build shelf --printer mk4                    # another printer profile
pixi run test
```

How arguments reach the `freecadcmd` script is up to the builder. odman uses environment
variables set by pixi tasks; any approach that gives the command-line experience above is fine.

Output in `out/shelf/<variant-name>/`: one STL and one 3MF per part (shelf, cleat, clips), a STEP of
the assembly, an `.FCStd` for opening in FreeCAD, and `summary.txt` with the parameters used, each
part's solid volume, estimated weight at 100 % solid (PLA 1.24 g/cm³), print orientation, and
build-volume fit. The variant name is derived from the parameters, or from the preset name.

## Printers

`printers.toml` holds named profiles: build volume (X, Y, Z), nozzle diameter, and fit clearance
(default 0.2 mm, used for anything that slides or clips together). Ship a handful of common
printers: Prusa MK3S (default) and MK4, Bambu Lab A1 and P1S/X1C, Creality Ender-3. These are my
call; any list is fine. A custom size can also be given on the command line.

Before exporting, every part is checked against the build volume **in its print orientation**. If
it doesn't fit, the build stops with a clear message saying which dimension is over and by how
much.

## The shelf

Coordinates used below: X along the wall (width), Y out from the wall (depth), Z up.

### Main parts of the body

- **Slab**: the horizontal surface, `width` × `depth` × `slab_thickness`.
- **Back plate**: vertical, against the wall, `plate_thickness` thick. It carries the mounting
  features.
- **Brackets**: vertical triangular gussets joining slab and back plate, `bracket_thickness`
  thick, with a concave **curved** outer edge (as in the spike: a rectangle minus an ellipse
  centred on its outer corner, leaving a `bracket_web` wide strip along both the slab and the
  plate).

All of these are one printed part.

### Supports below / above

- **`below`** (default): brackets under the slab. The back plate runs from the slab down to
  `bracket_height` below it. Brackets are spread across the width, inset from the ends (about
  width/6 for two brackets, as in the spike), so from the front the shelf reads as a thin floating
  slab.
- **`above`**: the slab hangs from brackets above it. The back plate runs from the slab up to
  `bracket_height` above it. Brackets sit **at the two ends**, flush with the sides, so they act as
  bookends instead of dividing the shelf into compartments. Extra brackets are added in between
  only when the gap rule requires it. (Ends-only placement is my call.)

### Mounting

The user picks one `mount` per shelf.

- **`screws`**: countersunk holes through the back plate, two "top" and two "bottom" for a 200 mm
  shelf. More are added on wider shelves, one pair per bracket gap, as a guideline. Holes sit
  between brackets, never behind one. The top holes resist the shelf's tendency to pull the top of
  the plate off the wall, so they must be as high as possible:
  - supports `below`, `top_screws = under` (default): top holes in the plate just under the slab
    (centre about 10 mm below the slab underside). The user confirmed a long screwdriver reaches
    them at 100 mm depth. Parameter `max_reach` (default 150 mm, my call: a typical long
    screwdriver shaft): if `depth` + `front_lip` exceeds it, the build refuses `under` and suggests
    `strip`, `keyhole` or `cleat`.
  - supports `below`, `top_screws = strip`: a short strip of back plate (about 18 mm) rises above
    the slab, and the top holes go there. Recommended for deeper shelves. It also stops items
    falling behind.
  - supports `above`: the plate is above the slab, so its top holes are near the plate's top edge
    and the bottom holes just above the slab. `top_screws` doesn't apply.
- **`keyhole`**: the same hole positions, but as keyhole slots: a head-entry hole with a narrower
  slot running **up** from it. The shelf goes over screws left slightly proud of the wall and
  drops down, so the screw ends at the top of the slot. The plate is locally thickened
  around each keyhole so the screw head has a pocket behind the slot and the plate still sits flat
  on the wall.
- **`cleat`**: a separate **French cleat** part, printed and exported alongside the shelf.
  - The wall cleat is a strip with a 45° bevel facing up and toward the wall, with countersunk screw
    holes. It is screwed to the wall first.
  - The shelf's back plate carries the matching 45° hook at its top edge. At its bottom edge there
    is a spacer of the same thickness as the cleat, so the shelf hangs plumb.
  - The cleat is slightly shorter than the shelf width.
  - Because the cleat is screwed up before the shelf goes on, screwdriver access is never an issue.
- **`adhesive`**: no holes. The back plate is always `full`, and taller than the other modes (a
  `min_bond_area` parameter, the builder's call on the default) to give tape or glue more area
  and a longer lever against peeling. Optional `glue_grooves`: shallow grooves on the wall-side
  face for hot glue to grip. The README says plainly that tape and glue hold only as well as the
  paint does.

### Material saving

- **`plate_style`**:
  - `full`: solid plate.
  - `windowed`: large rounded openings in the plate between brackets, keeping a frame around the
    plate edge, around every screw hole and keyhole, and where the brackets meet the plate.
  - `pads`: the leanest. Each bracket keeps its own mounting pad (a local section of plate,
    reinforced around its screw holes), and the pads are joined only by a narrow rail along the
    slab's back edge. In `pads` mode, holes move onto the pads beside each bracket.
  - `adhesive` mounting forces `full` and says so.
  - `cleat` mounting needs the hook to run continuously along the top, so `windowed` keeps it
    whole and `pads` puts a hook on each pad. The builder may decide `pads` + `cleat` is not
    worth supporting and refuse it with a message.
- **`surface = honeycomb`**: hex through-holes in the slab. Kept solid: a `solid_rim` border, a
  strip over each bracket, and a zone around each cable notch. Clips can go anywhere on the edge,
  because their grip depth is less than `solid_rim` (see clips).
  Hexes are oriented so they print without supports in the chosen print orientation (vertex
  pointing up the print's Z when the holes are horizontal in the print).
- Every build reports volume and weight, so variants can be compared. Slicer infill already
  hollows thick regions, but on 4–5 mm plates most plastic is top/bottom skin, so real cutouts
  save much more.

### Cable management

All optional. Cables come up the wall from below, so cutouts are on the **back** edge, close
against the wall.

- **Corner notch** (`back-left`, `back-right`): a quarter circle of radius `corner_notch_r` at the
  back corner. It also cuts a matching vertical channel through the back plate and any cleat or
  spacer, so the cable runs straight up the wall (as in the spike). For a shelf fitted into a room
  corner.
- **Back notch** (`back@<x>`, where x is the centre position from the left in mm; several
  allowed): a rounded slot `notch_width` wide, going into the slab from the back edge. It also cuts
  the plate below it, like the corner notch.
- Notches must not cut into a bracket, screw hole, keyhole or pad. The build refuses a collision
  and says what collides, or nudges the bracket if the builder finds that cleaner (builder's call).
  It never produces a collision silently.
- **Front lip** (`front_lip > 0`): a low rounded-top lip along the front edge so devices don't slide
  off.
- **Cable-tip clips**: separate small parts that push onto the shelf's front or side edge and grip
  a cable just behind its plug (micro-USB for PS4 controllers, USB-C for phones), so the plug stays
  on the shelf after the device is unplugged.
  - Sized from `slab_thickness` plus the printer's fit clearance (grip on the edge) and
    `clip_cable_d` (a C-shaped cable slot with a narrower entry so the cable snaps in).
  - They slide to any position along the edge; there are no fixed clip spots and no marks on the
    shelf (my call). The clip's grip depth onto the slab is less than `solid_rim`, so it never
    lands on a honeycomb hole.
  - They print several to a plate.
  - If `front_lip` is on, the clip must still fit over the edge, or the clip is designed for the
    side edges only (builder's call; say which in the README).
  - The exact clip shape is the builder's call; it should be small and tidy.

### Look

Plain and quiet, so the devices are what you notice. Thin slab, no decoration, all touchable edges
rounded (`edge_radius`), curved brackets. The user approved this look from the spike
(2026-10-23). There is no single "beautiful" target beyond that.

### Printing

- Print orientation is chosen per variant so no support material is needed. The guideline from the
  spike: lying **on the back plate** (wall side down) works for most variants. It gives a flat wall
  face for adhesive, vertical screw holes (no teardrops), and the slab and brackets grow straight
  up. Where another orientation is used, horizontal holes get teardrop shapes and overhangs stay
  ≤ 45°. The cleat prints lying on its back; the 45° bevel is self-supporting.
- A `--orientation side` option prints the shelf on its end, so each layer is a full L-profile.
  This is stronger, but the width is then limited by the printer's Z height. The fit check uses the
  orientation in effect.
- Exported meshes are already rotated into print orientation, so they drop straight onto the
  slicer bed.

## Testing

pytest, run inside the FreeCAD Python (`pixi run test`):

- For a representative grid of option combinations (each `supports` × `mount` × `plate_style` ×
  `surface`, with and without notches, lip and clips, at the default size plus one large and one
  small size): the body is a single valid solid, its volume is positive and plausible, and it fits
  the default printer or the build correctly refuses.
- Collision checks: notches vs brackets/holes, holes vs brackets, honeycomb vs solid zones.
- Refusals: out-of-range parameters, too big for the printer, `adhesive` with non-full plate
  (forced to `full` with a message), unsupported combinations.
- Clip fit: the clip's edge gap equals `slab_thickness` + clearance.
- Volume ordering sanity: `pads` < `windowed` < `full`, and honeycomb < solid.

Visual review stays manual: open the `.FCStd`, or use the FreeCAD MCP.

## Decisions log

The user's:
- Default size 100 × 200, all dimensions configurable. PLA.
- Mounting: screws, a separate wall part to hang on, or adhesive (tape / hot glue).
- Supports above or below as an option.
- Cable options: corner quarter-circle notch, cable-tip holders, and the other cable ideas, all
  optional.
- Repo `tridi` (github.com/havan/tridi) for this and future household projects; public; no personal information
  in tracked files (name in LICENSE and commits is fine). Licence CC BY-NC 4.0.
- Printer-agnostic; MK3S is the user's printer.
- Spike look approved; top screws under the slab must be an option (reachable at 100 mm depth).
- Material-saving modes: cut-away back plate down to pads, honeycomb slab.

Mine (open to change):
- French cleat as the wall part, keyholes as an extra option.
- 4 mm slab (spike had 5), 4 mm plate, 2 mm edge radius, curved brackets, bracket gap ≤ 160 mm.
- 14 mm notch width; 4 mm screw / 6 mm dowel defaults.
- Brackets at the ends for `supports = above`.
- Lying on the back plate as the usual print orientation.
- Clips as separate parts.
- Printer profile list; local.toml for personal presets.
- Honeycomb defaults 10 mm cell / 2 mm wall / 8 mm rim.
- Clips slide anywhere along the edge; no fixed spots.
- `max_reach` 150 mm for under-slab screws, refused beyond.
- Declare Linux, macOS and Windows in pixi; test on Linux only.
